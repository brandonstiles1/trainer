# Impromptu Workout — Start Any Plan Day's Workout from Today

**Date:** 2026-05-31
**Status:** Approved (brainstorming)

## Goal

Let the user start a workout on any day by picking one of their plan's existing days — even when today is a rest day, or when they want a second/different session on a training day. Example: nothing is planned for Sunday, but the user wants to do their Push workout.

## Decisions (from brainstorming)

- **Exercise source:** the user picks one of the active plan's existing days; that day's category + exercises are reused. Sets are generated by Claude from history exactly like a planned workout.
- **Where:** an inline box on `/today` (not a separate page). It shows on both rest days and training days.
- **In-progress handling:** `/today` already redirects to the session when a workout is in progress, so the box only renders when the user is free to start one. The action also resumes an in-progress workout if one somehow exists (preserves the one-active-workout invariant).
- **Day list:** the box lists **all** plan days, including today's planned category on a training day (simplest; the box is just "start any day's workout").
- **Recording:** impromptu workouts are normal `workouts` rows (`planId` = active plan, `dayKey` = chosen category, `status` = in_progress) and flow through commit/complete like any workout. `dayKey` records the category trained, not the calendar weekday.

## Components

### 1. Pure helper — `lib/workouts/find-plan-day.ts` (new)

```ts
findPlanDay(structure, day) // returns the PlanDay with matching `day`, or null
```

Isolates the lookup so it can be unit-tested without DB/Anthropic. `PlanDay` shape: `{ day: string; category: string; exercises: { name: string; order: number; notes?: string }[] }`. `structure`: `{ days: PlanDay[] }` (extra fields ignored).

### 2. Shared `createWorkout` helper — `lib/actions/workouts.ts` (refactor)

Extract the existing block inside `startWorkout` that (a) calls `generateWorkout`, (b) inserts the `workouts` row, (c) inserts the prescribed `workoutSets` rows, into a private helper:

```ts
async function createWorkout(params: {
  userId: string;
  planId: string;
  category: string;       // → workouts.dayKey
  exercises: string[];    // ordered exercise names
}): Promise<{ workoutId: string }>
```

`startWorkout` is rewritten to compute today's plan day and delegate to `createWorkout`. Behavior of `startWorkout` is unchanged (resume-in-progress, rest-day return, etc. stay in `startWorkout`).

### 3. `startImpromptuWorkout(sourceDay)` action — `lib/actions/workouts.ts` (new)

```ts
export async function startImpromptuWorkout(sourceDay: string):
  Promise<{ workoutId: string }>
```

1. Auth-guard (`not signed in` throw, matching existing actions).
2. Resume an in-progress workout if one exists → return `{ workoutId }`.
3. Load the active plan (throw `no active plan` if none).
4. `findPlanDay(structure, sourceDay)`; throw `plan day not found` if null.
5. Sort that day's exercises by `order`, map to names.
6. `createWorkout({ userId, planId: activePlan.id, category: day.category, exercises })`.
7. Return `{ workoutId }`.

### 4. Action forwarder — `app/today/actions.ts` (modify)

Add a `"use server"` forwarder mirroring the existing `startWorkout` wrapper:

```ts
import { startImpromptuWorkout as startImpromptuWorkoutImpl } from "@/lib/actions/workouts";
export async function startImpromptuWorkout(sourceDay: string) {
  return startImpromptuWorkoutImpl(sourceDay);
}
```

### 5. `ImpromptuBox` client component — `app/today/impromptu-box.tsx` (new)

Props:
```ts
{ days: { day: string; category: string; exercises: { name: string; order: number }[] }[] }
```

- Renders a bordered box (matching `/today`'s `rounded-lg border bg-muted/30` card style) with a header **"Choose an impromptu workout"**.
- Collapsed by default: tapping the header toggles open to reveal the day options (keeps it unobtrusive, especially under the main Start Workout button on training days).
- Each option is a tappable row: humanized category (e.g. `push` → "Push"), the weekday (capitalized), and a one-line exercise preview (names joined, `_`→space).
- Uses `useTransition` + `useRouter` (same pattern as `StartWorkoutButton`): on tap, calls `startImpromptuWorkout(day)` from `@/app/today/actions`, then `router.push(`/workout/${workoutId}`)`. Disable the rows while pending; show a brief "Generating…" state.
- Error: on throw, show an inline error message in the box (don't crash the page).

### 6. `/today` page wiring — `app/today/page.tsx` (modify)

- The active plan's `structure.days` is already loaded. Pass it to `<ImpromptuBox days={structure.days} />`.
- Render `<ImpromptuBox>` in **both** branches: after `<StartWorkoutButton />` on a training day, and after the rest-day card. (The page already returns early/redirects when a workout is in progress, so the box only shows when the user can start one.)

## Data Flow

```
/today (no in-progress workout)
  └─ <ImpromptuBox days=structure.days />
        └─ tap "Push (Monday)" → startImpromptuWorkout("monday")
              └─ resume-in-progress? else findPlanDay → createWorkout
                    └─ generateWorkout (Anthropic) + insert workout + sets
              └─ { workoutId } → router.push(/workout/{id})  → normal session
```

## Error Handling

- Action throws (`no active plan`, `plan day not found`, generation failure) propagate to the client; `ImpromptuBox` catches and renders an inline message, matching how `PlanDesignChat`/`StartWorkoutButton` surface failures.
- `createWorkout`'s insert mirrors the current `startWorkout` insert (no new transaction semantics introduced).

## Testing

- **`findPlanDay`** unit tests: returns the matching day; returns null when absent; ignores extra structure fields.
- **`createWorkout` refactor:** guarded by existing behavior — after refactor, run the full suite + `npm run build`; manually verify a normal `startWorkout` still works (no behavior change).
- **Manual:** on a rest day, open the box → pick a category → land in a session with that day's exercises; on a training day, the box appears under Start Workout and works the same; recorded workout shows the chosen `dayKey`.

## Out of Scope

- Designing a custom one-off workout with Claude (the "design with Claude" path was not chosen).
- Picking individual exercises à la carte.
- Multiple simultaneous in-progress workouts.
- A dedicated picker route/page (chosen the inline box instead).
